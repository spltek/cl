COMMAND LAUNCHER

Every alias, one-liner and three-week-old incantation in one drawer. cl keeps a name → shell command dictionary in a JSON file and hands you a single interactive picker to search it — while the command itself stays hidden.

No add/remove subcommands to memorise. No editor, no temp files, no shell config. One Go binary, three platforms, persisted to disk the instant you hit Enter.

    01 / WHY CL

    Built for the command
    you keep retyping.

    Personal command launchers usually punish you with config files and subcommands. cl is the opposite: one picker, one JSON file, and your fingers never leave the keys.

    One picker, zero ceremony

    There is no add or remove subcommand to remember. Run cl, type, press Enter. Adding is ctrl+a from inside the same list — where the command you just thought of already belongs.

    UXno subcommands

    The command stays hidden

    Names only, by default — so you can run something private in a shared screen without its value on display. ctrl+s peeks at commands; Enter always runs the real thing.

    privacydisplay-only toggle

    Placeholders, resolved live

    {{name}} and {{name:default}} are detected the moment you pick a command. cl asks for each value in sequence, then announces the resolved name before running it.

    templatingdefaults

    Written the moment you confirm

    Every add, edit, rename and delete lands in the JSON file immediately — not when you quit. Kill the terminal, lose the SSH session, crash the machine: your commands are already on disk.

    durabilityjson

    No editor, no temp files

    Editing happens inline, pre-filled and editable. Enter asks save? — y writes, n/esc leaves the stored command untouched. Duplicate or empty names are rejected in place.

    inlineguarded

    A single Go binary

    macOS, Linux and Windows from one static build. No runtime, no daemon, no background service, no telemetry — the picker exits the moment your command starts, and your shell takes over.

    go 1.250 deps

    02 / THE PICKER

    Ten keys.
    Everything else is typing.

    Filtering is a case-insensitive substring match — the whole typed text has to appear together, not its letters scattered anywhere. Arrows move, Enter runs, esc cancels.

    03 / PLACEHOLDERS

    Templates that
    ask nicely.

    Put {{name}} where a value goes and {{name:default}} where you usually reuse one. cl prompts for each in order, pre-fills the defaults, then announces the run in pink with the values in grey.

    • Required — {{name}} cannot be skipped; the run waits for a value.
    • Optional — {{name:default}} arrives pre-filled; Enter accepts it.
    • Visible — the list shows (user, host) or (remote[default:origin]) as a hint.
    • Independent — placeholders resolve whether or not commands are shown.

    04 / STORAGE

    A JSON file.
    That's the whole database.

    Commands live in your user config directory — never in a project, never in a dotfile you hand-edit. Writes happen as each add, edit, rename or delete is confirmed.

    config dir ~/Library/Application Support/cl

    Written on first launch. Installed to ~/.local/bin by the release installer.

    • Portable — copy the JSON to another machine and your commands come with you.
    • Readable — plain text, no lock-in, no migrations, no schema.
    • Inspectable — cat it, diff it, version it. It is just your commands.
    commands.json written immediately

    05 / SHELL STATE

    Some commands need
    a shell to live in.

    cl runs your command in a subshell. Builtins that mutate the shell — cd, source, export — evaporate with it. Append && exec $SHELL and the launcher replaces the subshell with a fresh interactive shell instead.

    the pattern
    cd ~/projects/target-folder && exec $SHELL

    Pick go to project and the current terminal is replaced by a new shell in the target directory — the cd actually persists.

    Regular commands — git, npm, docker, ssh — need nothing extra.
    commandwhy it needs && exec $SHELL
    cdChanges directory only in the subshell, then it's lost.
    sourceSources a file in a subshell, leaving your env unchanged.
    .Same as source — the dot builtin.
    exportSets env vars that disappear when the subshell ends.
    aliasDefines aliases that are lost when the subshell exits.
    unsetUnsets variables only in the subshell.

    06 / INSTALL

    Four ways in.
    No sudo, no admin.

    Every installer writes into your own home directory and edits your own shell rc files — plain per-user operations. Pick the one that matches your machine.

    $ brew install spltek/tap/cl

    The fastest path on macOS and Linux. Updates arrive through brew upgrade.

    installs to ~/.local/bin/cl · %LOCALAPPDATA%\cl\bin
    requires Homebrew · or build with Go 1.25+
    shell rc PATH updated per-user, never machine-wide
    Uninstall
    Homebrewbrew uninstall cl
    macOS / Linuxcurl -fsSL https://raw.githubusercontent.com/spltek/cl/main/uninstall.sh | sh
    Windowsiwr https://raw.githubusercontent.com/spltek/cl/main/uninstall.ps1 -UseBasicParsing | iex
    01

    Release binary

    Downloads the right binary for your OS and arch from the latest release. Override the destination with CL_INSTALL_DIR.

    02

    Build it yourself

    Go 1.25+. make install-local compiles and installs to ~/.local/bin, then prints the one command to activate it in your current shell.

    03

    Windows quirks

    If your execution policy is Restricted or AllSigned, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned first.
